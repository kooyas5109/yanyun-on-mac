# 候选版人工验证清单

候选版用于在不替换 `/Applications` 中正式版 App 的前提下，验证新版启动器能否安全复用现有游戏数据。

## 数据保护边界

- 候选版必须放在独立目录，且使用独立的 `CFBundleIdentifier`。
- 候选版继续使用目标游戏原有的 `appIdentifier`，从而复用
  `~/Library/Application Support/<appIdentifier>` 和其中的 `wine-prefix`。
- 测试期间不要点击“重置模拟器环境”。这是唯一会删除 Wine prefix 和已安装游戏的操作。
- 如果出现异常，退出候选版并重新打开 `/Applications` 中的正式版即可回退。
- 删除候选版 App 本身不会删除游戏数据。

## 开始前

1. 正常退出 `/Applications` 中的正式版模拟器。
2. 确认没有游戏或登录器窗口仍在运行。
3. 从独立候选目录启动名称带“候选版”的 App。
4. 如果 macOS 首次拦截本地测试签名，右键候选版 App，选择“打开”并确认。

## 验证项目

### 1. 识别现有安装

- [ ] 启动候选版后没有出现 Wine 环境重新初始化或游戏平台重新下载。
- [ ] 启动器直接识别到现有游戏平台并进入正常启动流程。
- [ ] 原有登录状态、游戏设置和资源仍然存在。

### 2. 登录与启动

- [ ] 登录窗口可以正常显示并完成登录。
- [ ] 游戏可以正常启动并进入主界面。
- [ ] 游戏画面、声音和输入没有出现新的明显异常。

### 3. 退出范围

- [ ] 从游戏内正常退出后，候选版恢复到可再次启动的状态。
- [ ] 再次启动游戏，然后使用“强制退出游戏”，仅当前候选版启动的游戏和当前
  `WINEPREFIX` 进程退出。
- [ ] 其他 Wine/CrossOver 应用以及 `/Applications` 中的正式版未被结束。

### 4. 诊断报告

- [ ] 点击“导出诊断报告”，选择一个容易找到的位置并成功生成 ZIP 文件。
- [ ] ZIP 中包含 `environment.txt`、`processes.txt`、
  `runtime-critical.sha256`、运行时版本清单以及可用的日志或崩溃报告。
- [ ] ZIP 中不包含 `wine-prefix`、游戏文件、Wine 注册表或账号凭据。

### 5. 重启后识别

1. 正常退出游戏和候选版。
2. 重启 Mac。
3. 再次从独立目录打开候选版。

- [ ] 重启后仍能直接识别现有游戏平台。
- [ ] 没有要求重新下载游戏。
- [ ] 登录并启动游戏仍然正常。

## 记录结果

若任一项目失败，停止继续操作，不要重置环境。记录失败步骤、屏幕提示和发生时间，
然后导出诊断报告用于排查。
